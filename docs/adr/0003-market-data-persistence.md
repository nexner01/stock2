# ADR 0003: 시장 데이터 저장과 정상 스냅샷 교체

- 상태: 승인
- 결정일: 2026-09-16
- 관련 문서: PDD FR-04, §8.3, §8.4, 구현 계획 M3

## 문제

최신 수집 시도는 실패하거나 부분 데이터일 수 있지만 사용자는 마지막으로 전체 검증에 성공한 데이터를
계속 확인할 수 있어야 한다. 실패 결과를 기존 정상 데이터에 합치면 완전한 최신 결과처럼 오인되며,
OHLCV를 부동소수점 또는 지역 시각으로 저장하면 분석 재현성이 깨진다.

## 결정

- OHLCV Decimal 값은 문자열, 시각은 UTC ISO 8601로 SQLite에 저장한다.
- OHLCV 식별자는 `symbol + exchange + interval + timestamp + source` 복합 unique constraint로 보장한다.
- `collection_runs`에는 모든 시도를 누적하고 `latest_collection_results`와 `healthy_snapshots`는 물리적으로
  분리한다.
- 한 transaction 안에서 run, 그룹 상태와 최신 결과를 기록한다. 상태가 `healthy`이고 전체 검증이
  성공했으며 공급원 기준 시각이 있을 때만 정상 스냅샷을 교체한다.
- 실패·부분 성공·검증 실패 payload는 최신 결과로 조회할 수 있지만 정상 스냅샷에는 합치지 않는다.
- quote와 index snapshot은 의미와 조회 패턴을 분명히 하기 위해 별도 테이블로 유지한다.
- 초기 seed는 migration에 포함하지 않고 테스트 fixture와 제품 seed 단계에서 별도로 관리한다.

## 대안

- 하나의 snapshot 테이블에 최신/정상 플래그를 두는 방법은 갱신 실수 한 번으로 복구용 데이터를 잃을 수
  있어 제외했다.
- 모든 값을 SQLite `REAL`로 저장하는 방법은 Decimal 직렬화 계약과 정밀도 요구를 위반해 제외했다.
- 실패 시 정상 행에 성공한 일부 심볼만 병합하는 방법은 부분 결과를 완전한 결과처럼 보이게 해 제외했다.

## 결과

저장 공간과 테이블 수가 늘지만 최신 장애 상태와 복구 가능한 정상 데이터를 독립적으로 조회할 수 있다.
M4 수집기는 검증 결과를 명시적으로 전달해야 하며 정상 스냅샷 교체 여부를 저장소가 transaction으로
보장한다.
