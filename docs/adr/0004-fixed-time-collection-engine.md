# ADR 0004: 고정 시각 그룹 수집 엔진

- 상태: 승인
- 결정일: 2026-09-16
- 관련 문서: PDD FR-12~FR-15, §8.3, 구현 계획 M4

## 문제

요청 완료 뒤 2초를 기다리는 방식은 공급원 응답 시간만큼 조회 시각이 계속 밀린다. 한 그룹의 지연이나
실패가 다른 그룹을 막거나, 일반 사용자 조회가 자동 조회의 실패 카운터를 바꾸면 화면 상태를 신뢰할 수
없다.

## 결정

- 공급원 세션 준비가 끝난 뒤 호출하는 `start()` 시각을 T0로 사용하고 모든 회차는
  `T0 + interval × n`으로 예약한다.
- `Clock`, `Scheduler`, `MarketDataProvider`와 snapshot repository를 port로 주입한다.
- 지수, 인기 종목, 관심 종목과 포트폴리오를 독립 상태 머신으로 유지한다.
- 실행 중인 그룹의 다음 회차는 요청을 중복 실행하지 않고 skip 횟수만 증가시킨다.
- 각 요청은 scheduler가 만든 timeout에서 실제 `AbortSignal`을 취소한다.
- 최초 실패 뒤 고정 시각에서 세 번 더 실패하면 그 그룹만 중단한다. 성공은 연속 실패를 0으로 만든다.
- 장 마감·휴장은 오류가 아니며 장중 전환 감지 시각을 새 T0로 삼는다. 기존 실패·중단 상태는 장 재개만으로
  초기화하지 않는다.
- 수동 조회는 같은 provider port를 쓰지만 자동 그룹 상태와 실패 카운터를 변경하지 않는다.

## 결과

수집 엔진은 실제 대기 없이 fake clock으로 모든 전이를 재현할 수 있다. 회차와 timeout 예약이 늘어나지만
그룹 독립성과 드리프트 없는 주기를 명시적으로 검증할 수 있다.
