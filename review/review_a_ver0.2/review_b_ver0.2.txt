# Stock2 Dashboard PDD v0.2.0 리뷰

전체적으로 데이터 정합성 원칙(임의 보간 금지, 분석 유형 구분, 상태 투명성)이 문서 전반에 일관되게 반영되어 있고, FR과 AC가 서로 잘 대응되는 탄탄한 문서입니다. 다만 몇 가지 짚어볼 지점이 있습니다.

**1. 2초 실시간 조회 요건이 가장 큰 리스크 (FR-12, 8.1, 13)**

이번 버전에서 "확정"으로 명시된 부분인데, 실행 가능성 검증이 아직 안 된 상태로 확정된 것처럼 보입니다.
- Yahoo Finance는 공식 실시간 API가 아니라 비공식 엔드포인트 기반이라 SLA가 없고, 종목 수가 많아질수록(주요지수 4개 + 인기종목 + 업종별 + 관심종목 + 포트폴리오 보유종목) 2초 간격 폴링 시 요청량이 급증해 IP 차단·레이트리밋에 걸릴 가능성이 높습니다.
- 13장에 "공급원 교체" 대안이 있지만, 2초 조회를 지원하는 무료/개인용 공급원이 실제로 존재하는지가 프로젝트 성패를 좌우하는 전제인데, 이 검증이 개발 착수 전 확인 사항으로만 남아있습니다. 이 검증을 문서 승인보다 먼저(스파이크 형태로) 해보는 걸 권합니다.
- "로컬 환경 기능 검증"이 MVP 완료 기준(11.4)인데, 2초 요건은 상용 서비스에 가까운 엄격도입니다. 개인 로컬 도구에 이 정도 실시간성이 왜 필요한지 근거가 문서에 없어서, 5~10초로 완화해도 사용자 경험에 큰 차이가 없다면 리스크 대비 실익을 재검토할 만합니다.

**2. FR-09 vs FR-10 기간 옵션 불일치**

- FR-09(보유 수량 기준 과거 추정 가치): 6개월, 1년, 3년, 5년, 7년, 10년
- FR-10(추천 포트폴리오 백테스트): 1년, 3년, 5년, 7년, 10년 (6개월 없음)

의도적 차이인지 누락인지 문서만으로는 판단이 안 됩니다. 백테스트에서 6개월을 뺀 이유(통계적 유의성 등)가 있다면 명시하는 게 좋겠습니다.

**3. FR-05 단기 기간의 데이터 가용성**

"1시간" 기간 옵션에 분 단위 데이터가 필요한데, Yahoo Finance 같은 무료 공급원은 분 단위 과거 데이터 제공 기간이 짧게 제한되는 경우가 많습니다(예: 1분봉은 최근 7일 정도만). 13장에 검증 항목으로 있긴 하지만, 이 제약이 실제로 걸리면 FR-01/FR-05의 "1시간" 옵션 자체가 무의미해질 수 있어 우선순위 높은 검증 항목으로 강조할 만합니다.

**4. MVP 범위가 넓음**

11개 기능(시황+검색+관심종목+포트폴리오 평가+과거 추정가치+백테스트+복사+데이터 상태)에 2초 실시간, FX 정렬 로직, 스냅샷 관리까지 들어가 있어 "MVP" 치고는 상당히 큰 범위입니다. 특히 리스크가 가장 큰 2초 실시간 조회를 가장 먼저 검증/구현하는 단계별 순서(예: 1차 - 정적 시계열/포트폴리오 계산, 2차 - 실시간 조회)를 문서에 명시하면 개발 우선순위 판단에 도움이 될 것 같습니다.

**5. FR-04 필수 필드에 간격(interval) 정보 없음**

`symbol, exchange, timestamp, open, high, low, close, adjusted_close, volume, currency, source`에 데이터 간격(1분/1일 등) 필드가 없습니다. 같은 종목의 여러 간격 데이터를 저장/조회할 때 구분자가 필요할 수 있어 보입니다.

**잘 된 점**: 7.6 환율 정렬 로직(이전 유효값 채우기 + 기준일 기록), FR-09의 종목 제외 UX(유지/제외/취소 3분기 + 미리보기), AC들이 Given-When-Then으로 FR과 촘촘히 매핑된 점은 특히 견고합니다.
